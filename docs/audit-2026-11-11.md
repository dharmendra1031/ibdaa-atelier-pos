## Confirmed in committed code

- ASP.NET Core `net10.0`, EF Core SQL Server `10.0.14`; Bootstrap `5.3.8` self-hosted LTR and RTL styles, basic bilingual Home and Catalogue.
- Cookie authentication with server-side Admin/Cashier roles, password hashing, logout POST and antiforgery; initial admin CLI requires locally supplied secret, no seeded password.

- Original website is untouched and has not been imported. No fabricated product prices are committed.

## Findings — ordered by urgency

| ID | Severity | Finding / evidence | Required correction or verification |
| --- | --- | --- | --- |
| A01 | **Blocker** | **Order, order-item snapshots, POS cart, payment, refunds, delivery, register closing and invoice generation do not exist** in committed source. | Build the transactional domain with independent Product/Service item types, per-item measurements, immutable pricing and safe retries before calling this an operational POS. |
| A02 | **Blocker** | No SQL application/verification, integration tests, authenticated browser E2E or physical print test evidence; CI only compiles and source-checks. | Add targeted xUnit, isolated SQL Server integration and browser tests; no claim of passing 19 SRS cases before execution. |
| A03 | **High** | ProductImages schema exists but there is no authenticated upload/replace/remove/gallery flow. SRS asks support for 4+ photos and primary selection. Category image/icon field is also absent. | Secure uploaded image content checks, path control, primary uniqueness, cleanup, thumbnails and category image support. |
| A04 | **High** | Client's existing catalogue source/API/export, product identities and image permissions have not been verified. Indexed site listings can differ. | Approved read-only export/API, source IDs and real asset mapping, dry-run diff + rerun dedupe, no automatic sync and no writes to the live website. |
| A05 | **High** | `CustomersController.Index` searches raw `search` in normalized `Mobile`; `PhoneNumbers.Normalize` strips Kuwait `965` when storing local numbers. Searching `+965 ...` may return no match. | Normalize mobile-like search terms using the same function as saves, preserving name and numeric customer ID search; test both prefixes. |
| A06 | **High** | `ProductSetupController` combines product + category measurement definitions without a defined precedence if both contain `Chest` with different units/required flags. Parent-category inheritance is also not specified. | Define override/merge policy, enforce duplicates and scope, and unit test same-name product/category definitions before cart integration. |
| A07 | **High** | Only roles `Admin` and `Cashier` are coded. SRS requires configurable permissions for discounts, refunds, report access and order edits; user CRUD is absent. | Add minimal numeric-ID permission model and enforced server policies before financial endpoints. Avoid a speculative permissions framework. |
| A08 | **High** | Login lockout is only per existing account, without rate limiting for unknown usernames; competing failed logins can race on `FailedLoginCount`. Data-protection key storage and reverse-proxy HTTPS behavior are unverified. | Add endpoint rate limiting, proper concurrency/lockout integration tests and deployment cookie/key/HTTPS checks. |
| A09 | **Medium** | `CatalogController` takes the first `100` products without pagination. Active catalogue beyond that is silently omitted. | Add stable server-side category/search pagination and UI page controls, not a larger unbounded first-load payload. |
| A10 | **Medium** | Current UI is not a finished premium POS. Arabic localization is partial (many errors, audit messages and status strings remain English). No actual responsive LTR/RTL screenshot audit exists. | Finish localization of user-facing strings and test 1366×768, tablet and mobile, including Arabic clipping and empty/filled states. |
| A11 | **Medium** | Measurement and size screens allow add, status toggle and chart value save, but do not implement full edit/update of definition labels, units, required flags or existing size names. | Add minimal editing paths with audit, scope validation and historical snapshot protection. |
| A12 | **Medium** | No consistent migration history/applied-version record or actual test restore evidence. Several scripts remain manually guarded and have been updated during development. | Maintain ordered, immutable versioned scripts with upgrade checks; verify from a fresh TEST DB and a migrated TEST DB before release. |
| A13 | **Medium** | Existing README and implementation checklist lag behind committed features: README says Admin login/editing not implemented. | Align status docs with actual verified source vs not-yet-tested behavior; never mark missing integration tests as passed. |
| A14 | **Medium** | No production concurrency/latency measurements, uploads persistence, compression/image transforms or actual shop hardware browser tests. | Add later after functional master/sale flows; measure rather than claim performance targets. |
