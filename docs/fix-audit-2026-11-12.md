## Release blockers and recommended next verification order

1. **VPS invoice print:** run a read-only test of `/Invoices/Print?id=<saved numeric ID>&paper=80mm`, verify HTTP 200 and PDF bytes, then browser print manually; inspect server logs if 500. Avoid creating a second invoice to troubleshoot printing.
2. **Source/SQL/Windows CI:** all jobs must pass for the same latest `fix` SHA; resolve any remaining test/schema regressions before merging.
3. **Cash accounting:** confirm register-opening policy, balance after refunds and cancellation/partial refund rules with shop owner; then add SQL concurrency tests without modifying production.
4. **Catalogue:** compare each live item price/photo to approved official source or owner list. Never publish assumed prices as verified.
5. **User journeys:** test login, new unpaid order, cash/KNET/WAMD split, extra tender/change, reprint, returning partial balance, discount, refund and delivery on an isolated seeded database.
6. **Screen QA:** compare approved Admin/POS/Login screenshots at desktop 1366×768, smaller tablet and mobile, English and Arabic, then consolidate overridden CSS rules only after regressions pass.

## Invariants

Keep `main`, `development`, live VPS and production SQL untouched until reviewed; no UUID/GUID persisted IDs, no silent retry duplicates, no deleting historical invoices, no unapproved pricing/financial-rule changes. Implement only minimal readable deltas with targeted tests.
